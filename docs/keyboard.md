# Keyboard

The 34xx InfoWindow terminals use IBM terminal keyboards: PS/2-style
synchronous serial keyboards that speak **scan-code set 3**. Two kinds exist:
the 122/124-key terminal keyboard (e.g. IBM 1394167) and the IBM Enhanced
101/102-key keyboard (e.g. IBM 1394193 / 1394204). The firmware is the same for
every country; **the keyboard selects the terminal's language** through the ID
it returns to Read ID (`F2`).

The emulator models the keyboard at the byte level (`src/input/set3_keyboard.*`)
and keeps the ID table in `src/input/keyboard_ids.*`. How each terminal's
keyboard interface is wired to the CPU differs per model; the 3477's interface
(`src/devices/ibm3477/keyboard_if.*`) is described in `docs/bringup-3477.md`.

Labels used below: **documented** (in a cited source), **observed** (reported
from real hardware by a cited source), **inferred** (our reasoning, to be
checked on a terminal).

## Protocol summary

Electrical layer (documented, IBM PS/2 keyboard reference): open-collector
clock and data lines; 11-bit frames (start 0, 8 data bits LSB first, odd parity,
stop 1). The keyboard clocks both directions. The host requests to send by
pulling clock low, then data low. The emulator does not model this layer; an
interface model will turn its register traffic into `host_write()` /
`read_output()` calls.

Keyboard-to-host bytes:

| Byte | Meaning |
| --- | --- |
| `AA` | BAT (self-test) passed, sent after power-on and `FF` |
| `FC` | BAT failed (not generated by the model) |
| `FA` | ACK of a command or parameter |
| `FE` | Resend: the last byte from the host was invalid |
| `EE` | Echo reply |
| `F0 xx` | Break code of key `xx` in set 3 |
| `00` | Key buffer overrun (set 3) |

Host-to-keyboard commands implemented by `Set3Keyboard`:

| Cmd | Name | Reply / effect |
| --- | --- | --- |
| `ED xx` | Set indicators | `FA`, then `FA` for `xx` (bit 0 Scroll, 1 Num, 2 Caps); `xx` > 7 gets `FE` |
| `EE` | Echo | `EE` |
| `F0 xx` | Select scan-code set | `FA FA`; `xx` = 0 returns `FA FA 03` (the model only ever emits set 3) |
| `F2` | Read ID | `FA id1 id2` |
| `F3 xx` | Typematic rate/delay | `FA FA`; delay = (1 + bits 6-5) × 250 ms, period = (8 + bits 2-0) × 2^(bits 4-3) × 4.17 ms; default `2B` (10.9 cps, 500 ms) |
| `F4` | Enable | `FA`; clears the key buffer, starts scanning |
| `F5` | Default disable | `FA`; defaults restored, scanning stops |
| `F6` | Set default | `FA`; defaults restored, scanning on |
| `F7` | All keys typematic | `FA` |
| `F8` | All keys make/break | `FA` |
| `F9` | All keys make only | `FA` |
| `FA` | All keys typematic/make/break | `FA` |
| `FB` / `FC` / `FD` `xx...` | Set listed keys typematic / make/break / make only | `FA` for the command and for each code; the list ends at the next command byte (≥ `ED`) |
| `FE` | Resend | the last byte the host read |
| `FF` | Reset | `FA`, then BAT `AA` (plus ID, see below) |

Any other byte ≥ `ED` gets `FE`. A command byte received while a parameter is
awaited starts a new command; parameters and key codes are all below `ED`.

Observed on the 122-key 1390876 ([seasip][seasip-1390876]): `F2` returns
`BF BF`; reset returns `AA` **followed by the two ID bytes**; `F0` is refused;
`FA` behaves like `FB`; the keyboard has no LEDs but checks the `ED` parameter
is 0–7. The model follows the IBM reference for `F0` and `FA` and, by default,
appends the ID after `AA` for the 122-key type only
(`Set3Keyboard::set_bat_sends_id`). Whether the terminals rely on this is
unknown.

### Scan-code set 3

Every key has one single-byte make code; a break is `F0` plus the make code.
There are no `E0` prefixes. Each key has one of four modes: make only,
typematic (make repeated while held), make/break, or typematic/make/break.
Only the last key pressed repeats.

Power-on defaults used by the model:

- make/break: Left Ctrl `11`, Left Shift `12`, Caps Lock `14`, Left Alt `19`,
  Right Shift `59`, and the Windows/Menu keys `8B 8C 8D`. This list is
  documented ([Brouwer][aeb-set3], citing the IBM reference).
- make only: Esc/F13 `08`, F1–F24, Print Screen `57`, Scroll Lock `5F`, Pause
  `62`, Num Lock `76`, Right Alt `39`, Right Ctrl `58` and the 122-key
  left-hand block. **Inferred** from the IBM key-type tables as remembered;
  check against the PS/2 Keyboards reference.
- typematic: every other key (inferred, as above).

The terminal firmware is expected to program the modes it wants with
`F7`–`FD`, so the defaults matter little. Linux, for example, sends `F8` for
IBM terminal keyboards ([atkbd.c][atkbd]).

## Keyboard IDs

The reply to `F2` is `FA id1 id2`.

- `id1` is the keyboard type: `BF` for 122/124-key and `7F` for IBM Enhanced.
  **Documented** for US keyboards: TMK lists 122-key terminal keyboards as
  `BFBF` and the IBM Terminal 101-key as `7F7F` ([TMK][tmk-proto]). We
  **infer** that national keyboards keep this first byte.
- `id2` is the country/layout byte. Its top two bits are `10` for 122-key and
  `01` for Enhanced, and the low six bits select the layout. The 1390876 sets
  bits 5–0 of the **second** ID byte with jumpers; one jumper turns `BF BF`
  into `BF 9F`, which is exactly the Data Entry – U.S. English ID below. This
  supports the second byte being the one the 3489 manual tabulates. It is
  still **inferred** until a terminal is observed.

(Linux only accepts first bytes `AB`, `AC`, `2B`, `5D`, `60` and `47` as
keyboards, so it does not recognise these keyboards natively. TMK's converter
treats any `BFxx` or `7Fxx` ID as a set-3 terminal keyboard.)

## Host key mapping

Host keys arrive as USB HID usages (SDL scancodes). They are mapped to the
set-3 key at the **same physical position**, not by legend. The terminal
firmware assigns each position its meaning (5250 functions, national
characters).

Same on both types: the main typing block, F1–F12 (`07 0F 17 1F 27 2F 37 3F
47 4F 56 5E`), the edit cluster (Ins `67`, Home `6E`, PgUp `6F`, Del `64`, End
`65`, PgDn `6D`), the arrows (`63 61 60 6A`), the keypad (Num Lock `76`, `/`
`77`, `*` `7E`, `-` `84`, `+` `7C`, Enter `79`, digits), Pause `62`, the ISO
keys (non-US `#` `53`, non-US `\` `13`), the modifiers (`11 12 19 58 59 39`),
and the Japanese keys (Ro `51`, Yen `5D`, Muhenkan `85`, Henkan `86`, Kana
`87`).

IBM Enhanced only: Esc `08`, backslash `5C`, Print Screen `57`, Scroll Lock
`5F`, Left/Right GUI `8B`/`8C`, Menu `8D`. Host F13–F24 are unmapped.

122-key only. These are host-mapping choices. The 122-key has an upper row of
12 function keys, a 10-key block left of the typing area, and extra keypad
keys; a PC keyboard has none of them.

| Host key | Set 3 | 122-key position |
| --- | --- | --- |
| F13–F24 | `08 10 18 20 28 30 38 40 48 50 57 5F` | upper function-key row |
| Esc | `05` | left block, row 1 left |
| Print Screen | `06` | left block, row 1 right |
| Scroll Lock | `04` | left block, row 2 left |
| Execute (HID 74) | `0C` | left block, row 2 right |
| Help (HID 75) | `03` | left block, row 3 left |
| Select (HID 77) | `0B` | left block, row 3 right |
| Application/Menu | `83` | left block, row 4 left |
| Stop (HID 78) | `0A` | left block, row 4 right |
| Left GUI | `01` | left block, row 5 left |
| Right GUI | `09` | left block, row 5 right |
| Backslash | `53` | key left of the ISO-shaped Enter (`5C` is hidden on 122-key boards) |
| Keypad `,` | `7B` | keypad row 3 right |
| Keypad `=` | `78` | under keypad Enter (hidden on IBM boards) |

The 122-key position between the left and right arrows (`62`) is reached via
Pause. Physical layout and codes are from the TMK converter's set-3 diagram
([unimap_trans.h][tmk-unimap]) and [seasip][seasip-6110344]. Most hosts have
no F13–F24, Execute, Help, Select or Stop keys. A general remapping layer in
the configuration is not implemented yet.

**Shift+F1..F12 enters F13..F24** (122-key keyboard, on by default; this is
the usual convention for terminal emulators on PC keyboards). Host F13–F24
keys, where present, still map directly. On a 122-key keyboard F13–F24 are
separate unshifted keys, so the terminal must not see Shift held while one of
them is pressed: the model sends the break code of each held Shift key
(`F0 12`, `F0 59`, if that key is in a break-sending mode) before the upper-row
make code, and the Shift make codes again after the upper-row key is released
if Shift is still held. Shift presses and releases while an upper-row key is
down are not reported; the final state is. Typematic repeat of the upper-row
key follows its own key mode. Disable the mapping with `--no-shift-fkeys` or
`[keyboard] shift_fkeys = false`. Enhanced keyboards have no F13–F24, so
Shift+Fn passes through unchanged there.

Typematic repeat is generated by the keyboard model (`advance_us`) from the
`F3` setting. Host auto-repeat (a second press without a release) is ignored.
