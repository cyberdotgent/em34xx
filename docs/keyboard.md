# Keyboard

The 34xx InfoWindow terminals use IBM terminal keyboards: PS/2-style
synchronous serial keyboards that speak **scan-code set 3**. Two kinds exist:
the 122/124-key terminal keyboard (e.g. IBM 1394167) and the IBM Enhanced
101/102-key keyboard (e.g. IBM 1394193 / 1394204). The firmware is the same for
every country; **the keyboard selects the terminal's language** through the ID
it returns to Read ID (`F2`).

The emulator models the keyboard at the byte level (`src/input/set3_keyboard.*`)
and keeps the ID table in `src/input/keyboard_ids.*`. How each terminal's
keyboard interface is wired to the CPU differs per model; the 3477's interface
(`src/devices/ibm3477/keyboard_if.*`) is described in `docs/bringup-3477.md`.

Labels used below: **documented** (in a cited source), **observed** (reported
from real hardware by a cited source), **inferred** (our reasoning, to be
checked on a terminal).

## Protocol summary

Electrical layer (documented, IBM PS/2 keyboard reference): open-collector
clock and data lines; 11-bit frames (start 0, 8 data bits LSB first, odd parity,
stop 1). The keyboard clocks both directions. The host requests to send by
pulling clock low, then data low. The emulator does not model this layer; an
interface model will turn its register traffic into `host_write()` /
`read_output()` calls.

Keyboard-to-host bytes:

| Byte | Meaning |
| --- | --- |
| `AA` | BAT (self-test) passed, sent after power-on and `FF` |
| `FC` | BAT failed (not generated by the model) |
| `FA` | ACK of a command or parameter |
| `FE` | Resend: the last byte from the host was invalid |
| `EE` | Echo reply |
| `F0 xx` | Break code of key `xx` in set 3 |
| `00` | Key buffer overrun (set 3) |

Host-to-keyboard commands implemented by `Set3Keyboard`:

| Cmd | Name | Reply / effect |
| --- | --- | --- |
| `ED xx` | Set indicators | `FA`, then `FA` for `xx` (bit 0 Scroll, 1 Num, 2 Caps); `xx` > 7 gets `FE` |
| `EE` | Echo | `EE` |
| `F0 xx` | Select scan-code set | `FA FA`; `xx` = 0 returns `FA FA 03` (the model only ever emits set 3) |
| `F2` | Read ID | `FA id1 id2` |
| `F3 xx` | Typematic rate/delay | `FA FA`; delay = (1 + bits 6-5) × 250 ms, period = (8 + bits 2-0) × 2^(bits 4-3) × 4.17 ms; default `2B` (10.9 cps, 500 ms) |
| `F4` | Enable | `FA`; clears the key buffer, starts scanning |
| `F5` | Default disable | `FA`; defaults restored, scanning stops |
| `F6` | Set default | `FA`; defaults restored, scanning on |
| `F7` | All keys typematic | `FA` |
| `F8` | All keys make/break | `FA` |
| `F9` | All keys make only | `FA` |
| `FA` | All keys typematic/make/break | `FA` |
| `FB` / `FC` / `FD` `xx...` | Set listed keys typematic / make/break / make only | `FA` for the command and for each code; the list ends at the next command byte (≥ `ED`) |
| `FA` `xx...` (122-key) | Set listed keys typematic (no break) | exactly as `FB` (terminal keyboard quirk, see below) |
| `FE` | Resend | the last byte the host read |
| `FF` | Reset | `FA`, then BAT `AA` (plus ID, see below) |

Any other byte ≥ `ED` gets `FE`. A command byte received while a parameter is
awaited starts a new command; parameters and key codes are all below `ED`.

Observed on the 122-key 1390876 ([seasip][seasip-1390876]): `F2` returns
`BF BF`; reset returns `AA` **followed by the two ID bytes**; `F0` is refused;
`FA` behaves like `FB`; the keyboard has no LEDs but checks the `ED` parameter
is 0–7. The 3477 firmware relies on the `FA` quirk: it sends `FA 61 6A`
(observed at every boot, after `FD 5A 58 11 7C` and an `FB` list of the
editing and keypad keys), so the 122-key model takes a key list after `FA`
and makes those keys typematic with no break code, exactly as `FB`
(documented by seasip: "Behaves as FB"). The Enhanced model follows the IBM
reference (all keys typematic/make/break). An earlier version set the listed
keys typematic/make/break; the firmware then reported every tap of the
horizontal cursor keys twice (once for the make, once for the break).
The model follows the IBM reference for `F0` and, by default,
appends the ID after `AA` for the 122-key type only
(`Set3Keyboard::set_bat_sends_id`). Whether the terminals rely on this is
unknown.

### Scan-code set 3

Every key has one single-byte make code; a break is `F0` plus the make code.
There are no `E0` prefixes. Each key has one of four modes: make only,
typematic (make repeated while held), make/break, or typematic/make/break.
Only the last key pressed repeats.

Power-on defaults used by the model:

- make/break: Left Ctrl `11`, Left Shift `12`, Caps Lock `14`, Left Alt `19`,
  Right Shift `59`, and the Windows/Menu keys `8B 8C 8D`. This list is
  documented ([Brouwer][aeb-set3], citing the IBM reference).
- make only: Esc/F13 `08`, F1–F24, Print Screen `57`, Scroll Lock `5F`, Pause
  `62`, Num Lock `76`, Right Alt `39`, Right Ctrl `58` and the 122-key
  left-hand block. **Inferred** from the IBM key-type tables as remembered;
  check against the PS/2 Keyboards reference.
- typematic: every other key (inferred, as above).

The terminal firmware is expected to program the modes it wants with
`F7`–`FD`, so the defaults matter little. Linux, for example, sends `F8` for
IBM terminal keyboards ([atkbd.c][atkbd]).

## Keyboard IDs

The reply to `F2` is `FA id1 id2`.

- `id1` is the keyboard type: `BF` for 122/124-key and `7F` for IBM Enhanced.
  **Documented** for US keyboards: TMK lists 122-key terminal keyboards as
  `BFBF` and the IBM Terminal 101-key as `7F7F` ([TMK][tmk-proto]). We
  **infer** that national keyboards keep this first byte.
- `id2` is the country/layout byte. Its top two bits are `10` for 122-key and
  `01` for Enhanced, and the low six bits select the layout. The 1390876 sets
  bits 5–0 of the **second** ID byte with jumpers; one jumper turns `BF BF`
  into `BF 9F`, which is exactly the Data Entry – U.S. English ID below. This
  supports the second byte being the one the 3489 manual tabulates. It is
  still **inferred** until a terminal is observed.

(Linux only accepts first bytes `AB`, `AC`, `2B`, `5D`, `60` and `47` as
keyboards, so it does not recognise these keyboards natively. TMK's converter
treats any `BFxx` or `7Fxx` ID as a set-3 terminal keyboard.)

## Host key mapping

Host keys arrive as USB HID usages (SDL scancodes). The emulated terminal has
a real IBM 122-key or Enhanced keyboard, and its firmware decides what each
key does, so the emulator turns PC keys into **terminal key positions**
(set-3 make/break codes), never into 5250 functions. Two layers do this:

1. the **host keymap** (`src/input/host_keymap.*`): rules that map a PC key
   plus the PC's Shift/Ctrl/Alt state to one terminal key, with the
   terminal's own Shift and Alt held or released around it;
2. the **positional fallback** for keys without a rule: the terminal key at
   the same physical place on the keyboard.

### Host keymap

Select it with `--keymap MAP` or `[keyboard] keymap = "MAP"`:

- `pcomm` (default): the default 5250 keyboard of IBM Personal
  Communications (PCOMM), which matches how the real terminal is used from a
  PC (Right Ctrl = Enter, Esc = Attention, Shift+F1 = F13, ...);
- `positional`: physical positions only (plus Shift+F1..F12 → F13..F24 on the
  122-key keyboard);
- a TOML file (below). `keymaps/pcomm-like.toml` is the `pcomm` map written
  out, `keymaps/positional.toml` the `positional` one; a unit test keeps
  them equal to the built-ins.

Engine behaviour:

- **Matching.** A rule names the host key and the modifier state. For each
  group (Shift, Ctrl, Alt) a rule requires it up (not listed), held on either
  side (`shift`), held on one side (`lshift`, `rshift`, `lctrl`, `rctrl`,
  `lalt`, `ralt` = `altgr`), or ignores it (`*`). The most specific matching
  rule wins (a side-specific condition counts 2, up/either 1, ignored 0);
  among equals the rule defined last wins, so a file overrides the built-ins.
- **Terminal modifiers.** The PC's Shift and Alt keys press the terminal's
  Shift (`12`/`59`) and Alt (`19`/`39`) keys. A rule can release or press
  them for as long as its key is down: break codes for the held ones before
  the key's make code, make codes again after its break if the PC keys are
  still held. Modifier changes while such a key is down are not reported;
  the final state is. The terminal has no Ctrl key: the PC's Ctrl keys only
  select rules (or press Reset/Enter, below).
- **Release.** The engine remembers what each host key pressed and releases
  exactly that, whatever the modifiers did meanwhile (Shift+F1 → F13, then
  Shift up, then F1 up releases F13). Two host keys on one terminal key give
  one make and one break.
- **Tap keys.** A `tap` rule sends its key (make, then break) when the host
  key is released, and only if no other key was pressed while it was held;
  otherwise the key was just a modifier. This is PCOMM's Enter/Ctrl and
  Reset/Ctrl behaviour for Right and Left Ctrl.
- **Typematic.** The keyboard model repeats the last key made from the `F3`
  setting; host auto-repeat (a second press without a release) is ignored.

## 5250 scan codes on the cable

Two different code sets are involved, and they must not be confused:

- **Keyboard to terminal**: scan-code set 3 (above), `F0` prefix for a break.
- **Terminal to controller**: the 5250 scan code in the second poll-response
  frame, one byte, bit 7 = break, 00h = no key, FFh = keyboard overrun
  (documented, PAI §2.4.3; `docs/twinax-bridge.md`).

The 3477 translates between them, and **the cable code set depends on the
keyboard** (observed, on the emulated firmware with every key position
pressed, unshifted, with Shift and with Alt):

- **Enhanced keyboard** (keyboard ID bit 80h): the set-3 make code of the key
  position, with bit 7 for a break; `83` is reported as `02` and `84` as
  `7F`. This is the PAI's Enhanced keyboard table (fig. 147), whose codes are
  the set-3 codes (F1 `07`, Enter `5A`, keypad minus `7F`).
- **122-key typewriter keyboard** (keyboard ID `02h`/`0Ah`): the **3180-2 /
  3196 codes of PAI fig. 105** (documented), placed by the key numbers of
  fig. 103. They are 5251-compatible:
  - one code per key position; letters are `11`–`1C` (A row), `21`–`2C`
    (Q row), `01`–`0A` (Z row), the digit row `3E 31`–`3C 3D`;
  - Shift is sent as make/break codes: left `57`/`D7`, right `56`/`D6`;
    Shift Lock `54`/`D4`. Alt is **not** sent;
  - **CMD prefix `6F`**: F1–F12 are `6F` + `31`–`3C` in lower shift, F13–F24
    the same in upper shift; Alt+key is `6F` + the key's code (Alt+digit-row
    keys give `6F 51`);
  - where a key needs a shift state (F1–F12 lower, F13–F24 upper, Insert
    lower, Delete upper: notes 1–4 of fig. 105), the terminal sends its own
    `57`/`D7` around it; the restoring code may follow later, just before
    the next key;
  - Insert and Delete share `6C` (lower / upper shift); Alt+Rule is `6D`
    (Home).

So host keys `a b c` reach the controller as `11 05 03` (observed), and F1
as `6F 31`. An earlier version of this page said the 3477 forwarded set-3
codes for both keyboards: that holds only for the Enhanced keyboard. The
firmware has a third mode that sends set-3 codes for the 122-key keyboard too
(breaks as `F0 xx`); it is selected by a setup value (hypothesis: a setup
option not yet identified) and is not the default.

| keypad | `76 77 7E 84`→`1D 1E 4F 50`; `6C 75 7D 7C`→`47 48 49 4E`; `6B 73 74 7B`→`44 45 46 55`; `69 72 7A 79`→`41 42 43 4D`; `70 71`→`40 4A` |
| F keys | lower row `07 … 5E`→`6F` + `31`–`3C` (lower shift); upper row `08 … 5F`→`6F` + `31`–`3C` (upper shift) |
| Alt | `6F` + the code; Alt+Help `6F 3E` (Hex), Alt+Play `6F 3D` lower (Test), Alt+`06` `6F 3D` upper (Clear) |

The controller learns the layout from Read Device ID to the keyboard address
(`2C`): `02h` typewriter (US), `0Ah` world trade typewriter, and bit 80h set
(`82h`/`8Ah`) for the Enhanced keyboard (documented, PAI fig. 41; observed,
the 3477 sets `02h` only when the keyboard's country byte is `3F`).

The terminal keeps some keys for **local functions** and never sends them
(observed in the firmware; legends from the 3489 User's Guide, GA18-7492,
§4.2.7):

| Keyboard | Keys kept by the terminal |
| --- | --- |
| 122-key | `01` Setup; `09` Record; Alt+`09` Pause; `0A` Play; `62` Rule; `03` Print when local print is configured; Alt+`11` Quit; Alt+`6F` Jump; Alt+`67` change screen format; Alt+`47`/`4F` split-screen Back/Fwd |
| Enhanced | Shift+Esc Setup; Alt+F4 Record; Alt+F5 Play; Shift+Pause Pause; Alt+Left Ctrl Quit; Alt+PgDn Rule; Alt+PgUp Jump; Alt+Insert change screen format; Alt+F9/F10 Back/Fwd; Print Screen when local print is configured |

### 122-key typewriter table (`src/host/wsc/keyboard_map.cpp`)

The controller decodes the fig. 105 stream back to key positions (tracking
`57`/`56` shift, `54` Shift Lock and the `6F` CMD prefix, which sets the
action's Alt flag), then looks the position up below. US functions and US graphics (EBCDIC CCSID 37). Sources, in order of weight:
the 3489 User's Guide key tables (§4.2.2–4.2.8, which show this 122-key
keyboard next to the Enhanced one, with the keys of each group marked in a
layout diagram); a top-down photo of a genuine IBM 1394324 "5250 converged
typewriter" keyboard (UK legends; Sharktastica, see Sources), which gives
every legend at its position; and the TMK converter's set-3 map, which gives
the set-3 code at each position. Where the guide's diagrams show a key, they
agree with the photo. Front legends (lower edge of the keytop) are entered
with Alt; the upper legend of a two-legend keytop with Shift.

Unmapped: the blank keytops `02 04 06 6F 7B 76 77 7E 7F` and the keys the
terminal keeps (`01` SetUp, `62` Rule). They reach the session as
`Unmapped` with the raw code. There is no Field Mark key on the typewriter
layout (the 3489 guide lists none).

**National layouts.** The cable gives no way to tell countries apart: the
3477 reports `02h` for the US keyboard and `0Ah` for every other country
(observed), so a controller must be told the country by configuration, as
the AS/400 device description does. The table therefore uses US graphics for
every ID (hypothesis for non-US keyboards). The UK 1394324 photo shows how
far national 5250 legends depart from PC layouts, so they cannot be borrowed
from PC tables: `0E` \ (shift ¦), `26` 3 (shift £), `45` 0 (shift #),
`4E` - (shift =), `55` ¬ (shift −), `54` @ (shift \`), `5B` {, `53` },
`4C` ; (shift +), `52` : (shift \*), `13` an extra key left of Z. Adding UK
and other tables needs a country setting and the CCSID 285 (etc.) code
points; the 3489 User's Guide appendix I has the national layouts as figures
(not yet transcribed).
